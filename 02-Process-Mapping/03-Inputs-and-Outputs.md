# Inputs and Outputs Analysis

## Purpose

This document identifies the main inputs and outputs involved in the student support request process.

Understanding the inputs and outputs helps identify what information is required at each stage of the process and what results should be produced.

The analysis is based on the fictional Cape Learning Institute (CLI) case study and simulated stakeholder findings.

## Process Inputs

Inputs are the information or resources required for the student support process to begin and continue.

### Main Process Inputs

| Input | Description | Source |
|---|---|---|
| Student Details | Information used to identify the student | Student |
| Support Request | The issue or assistance the student requires | Student |
| Request Description | Details explaining the student's problem or question | Student |
| Request Category | The type of support required | Student / Support Staff |
| Supporting Information | Additional information or documents required to understand the request | Student |
| Communication Channel | The channel through which the request is received | Student |
| Staff Information | Information about staff members available to handle requests | Support Department |
| Request Status | Information showing the current stage of a request | Support Staff |

## Input Details

### Student Details

Student details may include information such as the student's name, student number and contact information.

This information allows support staff to identify the student and communicate with them regarding the request.

### Support Request

The support request describes the assistance required by the student.

Examples include:

- Academic assistance
- Registration problems
- Financial queries
- Course or module information
- Technical issues
- General student assistance

### Request Description

The request description provides more detail about the student's issue.

Clear information is important because support staff need to understand the problem before determining how it should be handled.

### Request Category

The request category helps support staff determine what type of assistance is required.

Categorising requests can also help with assigning requests to appropriate staff members and producing management reports.

### Supporting Information

Some requests may require additional information before they can be handled.

This could include supporting documents, screenshots, registration information or other relevant details.

### Communication Channel

The current process uses several communication channels:

- Email
- WhatsApp
- Telephone
- In-person visits

Using multiple channels creates a challenge because request information may initially exist in different locations.

## Process Outputs

Outputs are the results produced by the student support process.

### Main Process Outputs

| Output | Description | Recipient |
|---|---|---|
| Recorded Support Request | A support request recorded for tracking and management | Support Staff |
| Assigned Request | A request allocated to the appropriate staff member | Support Staff |
| Request Status | The current state of the support request | Student / Support Staff / Manager |
| Student Response | Information provided to the student regarding their request | Student |
| Resolved Request | A support request that has been addressed | Student / Support Department |
| Updated Request Record | The final information recorded about the request | Support Department |
| Management Information | Information about request volumes, workload and performance | Support Manager / Management |

## Output Details

### Recorded Support Request

The request should be recorded with sufficient information for support staff to understand and manage it.

### Assigned Request

The request should be assigned to the appropriate staff member so that responsibility for handling the request is clear.

### Request Status

The request status provides information about the progress of the request.

Possible statuses could include:

- New
- Assigned
- In Progress
- Awaiting Information
- Referred
- Resolved
- Closed

### Student Response

The student should receive a response explaining the outcome of their request or providing any information required from them.

### Resolved Request

A request becomes resolved when the student's issue has been addressed and no further action is required from the support team.

### Updated Request Record

The request record should be updated with relevant information about the actions taken and the final outcome.

### Management Information

Structured request information can be used to provide management with information such as:

- Number of requests received
- Number of outstanding requests
- Number of overdue requests
- Request categories
- Staff workload
- Average response time
- Average resolution time

## Input and Output Problems in the Current Process

The current process has several issues relating to inputs and outputs.

### Input Problems

- Requests are received through multiple communication channels.
- Information may be incomplete when a request is first received.
- Information may be recorded differently by different staff members.
- Supporting information may need to be requested separately.
- Duplicate requests may occur when students use more than one communication channel.

### Output Problems

- Request status may not always be immediately visible.
- Students may have limited visibility of request progress.
- Management information requires manual compilation.
- Overdue requests may be difficult to identify.
- Information may become outdated if spreadsheets are not updated consistently.

## Improvement Considerations

The future-state process should aim to improve the way inputs are captured and outputs are produced.

Potential improvements include:

- Standardising the information required when a request is submitted.
- Centralising support request information.
- Providing a unique reference number for each request.
- Using defined request categories.
- Using standardised request statuses.
- Clearly recording request ownership.
- Improving visibility of outstanding and overdue requests.
- Structuring information so that management reports can be produced efficiently.

These improvements will be considered when developing the future-state To-Be process.

## Case Study Note

This is a fictional Business Analysis portfolio case study. The inputs, outputs and process relationships represent simulated analysis based on the defined business problem and stakeholder findings.

No real stakeholder interviews or observations were conducted.
